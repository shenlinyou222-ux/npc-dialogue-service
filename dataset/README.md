## 4. 四个问题的修复方式

### ① 训练/推理格式不一致 ⭐

**推理时真实使用的 prompt**（逐字取自 `/home/user/vcf.py` 的验证矩阵，即父代理验证 LoRA 时实际发出去的输入）：

```
（开拓者朝你走近了两步）                                        ← 纯动作，无前缀
三月七，你今天看起来很有精神啊。                                  ← 裸输入
【场景：即将进入战斗，气氛紧张】\n开拓者：准备好了吗？              ← 场景 + 带说话人历史
```

**旧数据的根本问题**（用同一个解析器实测）：

- `97.8%` 的样本含 `【任务：XXX】` —— 游戏里不存在这种输入，推理时永远不会出现；
- **`100%`** 的样本把 `【场景：Y】` 与 `【任务：X】` **挤在同一行**，永远无法对应推理时独立的 `【场景：X】` 行；
- 有 `1253` 条结构化样本内部混着**无说话人的裸行**，结构不自洽；
- `5060/5092` 条都是"裸输入"形态，而推理主力形态（占 6/10）是 `【场景：】+对话历史`。

**v2 的做法**：user 段只有两种成分 —— `【场景：<推断描述>】` 与 `说话人：台词` / `（动作）`，
并**同时覆盖推理实测的 4 种输入形态**（`variant` 字段）：

| variant | 形态 | 训练集占比 | 对应推理场景 |
|---|---|---|---|
| `scene_dialogue` | `【场景：X】` + 说话人：台词（多轮） | 56.6% | 战斗前/战斗后/看雪/回忆/危险/告别 |
| `scene_action` | `【场景：X】` + `（动作）` | 10.3% | 看雪 |
| `bare_action` | `（动作）`，无场景前缀 | 15.8% | 打招呼 |
| `bare_line` | 一句话，无任何前缀 | 17.2% | 被夸奖/抱怨累/感谢 |

**场景描述如何推断**：`region` 字段映射地点（如 `雅利洛-Ⅵ → 贝洛伯格`）×
`section`/上下文关键词推断情境（如 `夜谈`/`气氛紧张`/`闲聊`），合成如
`贝洛伯格，看看为什么有人堵路`、`仙舟罗浮，夜谈`。**不含任何 Wiki 任务名**。

### ② 样本严重冗余

以游程为单位合并：`4021` 个游程 → 按"连续片段"切块，一个 mission 产出约 2–5 条。
每 mission 平均样本数由 **29.8 → 6.6**，而覆盖的 mission 数由 **183 → 207**（反而更多）。

### ③ 输出过短

- 连续多轮台词**合并成一段 assistant**（`--max-merge-lines 2`）；
- 长游程按 cap 切块，让**前一块成为上下文**，形成"同一场景的不同切片"（续写样本）；
- 单行游程只保留较长台词（`>=24` 字），且地区配额内优先取更长者。

用 `calibrate.py` 在"合并轮数 cap × 单行补量 S"上搜索，选定 `cap=2`：
assistant 均值 **13.9 → 28.9 token**（+108%），p50 **12 → 27**，p90 **25 → 45**。

### ④ 无多样性

- **4 种输入形态** × **2/3/4 轮上下文窗口** × **3 种 channel**（mission/sms/voice）；
- 按 `region` 分层配额抽取单行样本，保证地区覆盖；
- 角色语音层覆盖**战斗场景**（战斗开始/受击/终结技/战斗胜利…）；
- 长游程切片提供"同一场景的多种反应"。

## 5. 切分方式

**按 `mission` 切分**（同一任务内上下文高度重叠，随机切会泄漏）：

- train 1289 条 / 198 个 mission；val 68 条 / 9 个 mission；
- **mission 重叠 = 0**；
- val 比例 5.0%。切分时先排除"超大 mission"（否则 2 个 mission 就能填满 val，
  val_loss 只反映单一剧情线），再贪心挑选最接近目标量的组合，使 val 与 train
  的台词长度分布接近（28.3 vs 29.0 token）。

## 7. 已知局限与注意事项

1. **85 条角色语音样本使用合成上下文**（`synthetic_context=1`）。语料中的角色语音是
   孤立台词、没有上下文，脚本按 `section` 合成了"忠实但合成"的触发情境。
   这些情境刻意对齐推理实测的场景（战斗前/战斗后/危险/告别…），但**不是真实剧情**，
   可随时用 `synthetic_context` 字段剔除。
2. **`__voice__/*` 是伪 mission 名**，用于让这些样本在按 mission 切分时不被拆散。
3. **单行样本存在长度偏置**：地区配额内优先取更长台词（这是为达成问题③目标的有意选择），
   会让单行样本比"随机抽样"略长。
4. **已剔除**：系统/UI 提示旁白（`（获得物品）`/`（进入战斗）`/`（敌方血量少于一半）`）、
   被涂黑文本（`▇ ▇ ▇`）、复读上下文的样本（阈值 0.55，宁可多丢几条例）。
5. 训练脚本 `train_lora.py` 未改动；本目录只做数据，**没有训练模型**。
